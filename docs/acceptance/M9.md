## Modelling decisions (slice 1)

1. **What is typed goes as a board's serial console takes it**: a ring of characters in the Control buffer (after the input slots), read by the worker; `\x03` in it never reaches the text but raises KeyboardInterrupt (`mp_hal_set_interrupt_char`), what was typed before it stays. Text typed while nothing reads waits for the next `input()`, as on a board.
2. **The REPL runs in the session's worker**: the worker tells the program's end (`ended`) and goes on taking lines until Stop; Stop at the REPL ends the worker at once (nothing runs to stop). It keeps the circuit the program started with, so a changed circuit ends it.
3. **Timers and IRQs go on at the REPL and in input()**: the wait is the board's sleep, as after main.py on a board (no soft reset until Ctrl+D).
4. **The window's banner, not the board's**: after the program, the console says *main.py ended. Its names are still here…* (screen 29c) instead of the board's `MicroPython v1.29.0 on …; Type "help()"` lines.
5. **Explanations never replace MicroPython's message**; they are keyed on its exact texts and say nothing for an error they don't know (the student's own exceptions, KeyboardInterrupt). Branches for messages MicroPython never prints ("expected an indented block", "can't convert 'int' object to str implicitly") were dropped.
6. **"More about NameError"** (screen 05's second button) waits for M8 Learn, which it links to.

## Modelling decisions (slice 2)

1. **A burnt LED stays dead** until it is replaced (screen 04's *Replace the LED*), as a real one would: the next run leaves it out of the circuit (open). It is kept for the session, not in the project file; an LED deleted is forgotten. A **damaged pin is not kept**: on a real board it may be dead too, but a pin that never works again would stop the lesson — it is ringed and said, and Undo is offered.
2. **"Show me how"** (screens 04, 25c: the book icon) opens the part's Learn page: it waits for M8, as slice 1's *More about NameError*.
3. **The card's numbers are the engine's**: a motor on a pin says what the pin gave (≈ 46 mA, all a Pico W pin gives), not what the motor would like (screen 25c drew 160 mA).
4. **Problems opens by itself only on a damage** (the run stopped: why is the next thing to read); warnings while running are counted on its tab and noted on the canvas, the console stays.
5. **An LED the wrong way round** is a warning only for a plain LED with more than 1 V across it backwards: a 7-segment digit's or an RGB LED's dies can't be turned, and an LED with no voltage across it says nothing.
6. **Clear** in Problems empties the run's faults; an LED still dead stays listed (it is the circuit's state, not the run's).

## Modelling decisions (slice 3)

1. **Only legs a part can't do without** are checked, in a part that is in use (something is joined to one of its points): an RGB LED's unused colour, a button's second leg of a pair, a part lying unwired on the breadboard say nothing. No part model says which legs are optional, so the list is MicroLab's (`NEEDED`, plus every VCC and GND).
2. **"Where nothing else is" is the column itself**: what is in it with the wires taken out — another part's leg, a board pin, a wire's end. A wire's own far end doesn't count.
3. **A pin is wired** when anything is on it — a wire to an empty column too (the wire check says that one): each mistake is said once.
4. **Only the file Run runs is read**, and only literal pin numbers (`Pin(n)` from a variable is left alone): the check never guesses.
5. **The check is on by default**; *Check each time I press Run* and Run's ⌄ menu turn it off and on, remembered. Restart and Ctrl+D (the REPL) don't check: the student already chose to run.

## Findings (slice 3)

1. The first rule for wires counted a wire's far end as something in its column (a wire joins its two ends): every wire looked joined. The check now looks at each column without the wires (decision 2).
2. The save e2e test's starter circuit (a resistor with one end wired) now stops at the card: the test presses Run anyway — the card in the real app.
3. The full e2e run caught a race in M7.5's test (the program ended on its UnicodeError, taking the terminal card, before *Garbled?* was read): the board now sends a dot every half second, so the garbage shows while it runs, and then *off* is sent.

## Findings (slice 2)

1. Written into a test as it was, "They asks" for NeoPixels with no part to name, and an empty name for a motor fault with no part: both fixed (the tests now say *It asks*, *The motor is wired …*).
3. The full e2e run (61 / 62) caught slice 1's Ctrl+C at the REPL under load: the worker read the block's empty line and the Ctrl+C at once, and the REPL waiting at `...` took the Ctrl+C first — the block was dropped, nothing stopped. Ctrl+C now keeps its place when it comes while input() or the REPL waits (the lines with it are taken first, as a board takes bytes as they arrive); while nothing reads it still stops the program at once, lines typed before it left unread (`src/sim/stdin.ts`, `tests/unit/sim/stdin.test.ts`, 5).
2. An LED burnt in one run had nothing left to replace it from after the next run (its fault belongs to the run that burnt it): Problems now lists *LED1 is still burnt out* with Replace, and the canvas shows its card, until it is replaced.

## Findings (slice 1)

1. A line running at the REPL prints no prompt: the console's field was named after the prompt shown and lost its name mid-line (the e2e test found it). It is now named for the session (the program, or its REPL).
2. The canvas note took `role="status"`, which the status bar has: it is a `note`.
