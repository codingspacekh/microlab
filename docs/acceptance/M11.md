## Decisions

1. **As the gradebook and OneEditor do it** (surveyed 2026-11-09): electron-builder; a generic update feed on a GitHub release (`https://github.com/<owner>/<repo>/releases/latest/download`); electron-updater looking 8 s after start and every 6 hours, `autoDownload` off (the student's choice), installing on *Restart and update* or at quit; Macs signed with the teacher's own certificate (`CSC_NAME`), not notarised; Windows NSIS x64 per user, unsigned; `whats-new.json` per version.
2. **Releases in a releases-only public repo** (the teacher), as the gradebook's: the code stays private — *© 2026 CodingSpaceKH. All rights reserved.*
3. **The Windows installer built by GitHub Actions** (the teacher), as OneEditor's: a version tag builds it into a draft release; the Mac adds its installers; the teacher publishes.
4. **The app icon is the logo itself** (the teacher): one picture for the app everywhere.
5. **Ported, not rewritten**: OneEditor's update logic, its tests and its fix for electron-updater's default export come over as they are, adapted to MicroLab's names; the gradebook's and OneEditor's wording stays (*is out*, *Restart and update*, *Updated to*).
6. **Restart and update never loses work**: the project's changes, then each Python file's, are asked about before MicroLab restarts.

## Findings

1. **Some pieces of the code fonts (M12 Rev 12) were refused by the window's security policy** (`font-src 'self'`): Vite inlines small files as `data:` URLs. Fonts are never inlined now; a test checks that the window loads with nothing refused.
2. A test sent a menu action before the window had started listening; a real menu click comes after the window is up — the test waits for it.
3. The real MicroPython tests (WebAssembly) can pass 5 s under the full run's load since M12's CPython tests joined it: their project's limit is 15 s.
4. Everything the window uses was in `dependencies` — electron-builder would have shipped it twice (bundled, and from node_modules): only the main process's runtime packages stay.
5. **The installed app had no firmware for Install MicroPython**: `library/` isn't packaged — the firmware is a resource of its own now, and the self-check looks for every file firmware.json names.
6. **The first run of the tests on Windows** (GitHub Actions, 2026-11-09) — 9 of 164 test files: the checkout turned text into CRLF, so files compared byte for byte (golden circuits, the library pack's SHA-256s, the examples) differed — `.gitattributes` keeps LF; a Mac's or Linux's drive path was joined with `\`; an example folder was named *BBC micro:bit V2* (Windows refuses `:`); **Ctrl+C in `turtle.done()` never arrived** — Tk's mainloop waited for an event a quiet window never sent: a tick every 0.1 s (a real fix for students on Windows); **`open('.')` on Windows is a PermissionError**, not IsADirectoryError — explained as a folder now; Windows won't remove a folder a running Python is in; chmod doesn't lock a folder there; a raw-paste test gave the fake board only 60 ms.
7. ESLint read the packaged app's own files in `release/` (pip's JavaScript): `release/` and `build-info/` are ignored.
